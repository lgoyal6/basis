basis.

A ledger that argues with your broker.

Given the same trades your broker saw, basis replays them through a multi-commodity double-entry ledger, applies corporate actions, computes lot-level cost basis, and compares its answer against the position the broker reports. Every disagreement becomes a break with a probable cause attached.

Three answers, not two

Most tools tell you the numbers disagree. The useful part is why, and how much the tool actually knows. basis keeps those apart on purpose.

UNAPPLIED_SPLIT (confirmed)

The ratio matches, and split history confirms a split on that date. Confident enough to name the action and hand you the command.

UNAPPLIED_SPLIT (suspected)

The ratio matches, but nothing was ever fetched to check it against. That is arithmetic, not evidence, and it says so rather than guessing.

RATIO_WITHOUT_KNOWN_SPLIT

History was checked and contains no such split. The ratio is a coincidence, so this points at missing trades instead.

“Checked and found nothing”, “never checked” and “could not check” are three different states. Collapsing them into one is how a tool ends up confidently wrong.

Run it yourself

The session above, on your machine, in one command. No API key, no data of your own, and it tears the database down when it finishes. Needs JDK 21 and Docker.

git clone https://github.com/lgoyal6/basis && cd basis
./scripts/demo.sh

To point it at your own history instead:

docker compose up -d          # Postgres 16, the only dependency
./gradlew bootJar

# what you held before your oldest statement
basis open Assets:Broker:Fidelity AAPL 100 --cost 90.00 --on 2015-03-12
basis import fidelity Assets:Broker:Fidelity history.csv
basis reconcile Assets:Broker:Fidelity positions.csv --as-of 2026-03-31

What it refuses to do

  • It is not a tax product. It does not generate tax forms.
  • It does not guess. An unreadable statement row stops the import and prints the wording it did not recognise. An ambiguous corporate action raises a break and asks.
  • It never touches broker credentials. Statement upload only, no OAuth, no screen scraping, no stored passwords.
  • It computes nothing in your browser. This page is a recording. The hosted version is a real server, but it renders what the same Java ledger returned rather than reimplementing any of it, so there is never a second answer to disagree with the first.
  • It stores nothing it does not have to. An uploaded statement is held in memory for two hours and deleted on request. It is never written to a database, because a promise to delete is only as good as the backups and a promise that nothing was written down can be checked by reading one file.
  • It uses no floating point. Anywhere. An ArchUnit test fails the build if a double appears, because binary floating point cannot represent 0.10 and a basis that drifts a cent per trade is wrong in a way nobody notices for years.
